# DeskAgent 3D 角色模型规范

> **给 3D 美术的交付要求文档。** 本规范定义了 DeskAgent 桌面伙伴产品所需的 5 套 rigged GLB 模型的技术要求。模型将被 Three.js (WebGL) 实时渲染引擎加载，在用户桌面上以 60fps 持续运行。

---

## 1. 交付物总览

需要 **5 个物种** 的基底模型，每个物种一个 GLB 文件：

| 文件名 | 物种 | 说明 |
|--------|------|------|
| `human.glb` | 人类 | 写实风，作为默认/最常用物种 |
| `elf.glb` | 精灵 | 修长体型，尖耳，空灵气质 |
| `spirit_beast.glb` | 灵兽 | 可双足或四足，动物特征 |
| `mecha.glb` | 机甲 | 机械结构，金属材质，关节式运动 |
| `shapeshifter.glb` | 幻形 | 中性基底，高度可塑 |

**交付路径**：`backend/assets/base-models/<文件名>.glb`

---

## 2. 文件格式

| 项目 | 要求 |
|------|------|
| **格式** | glTF 2.0 二进制（`.glb`） |
| **纹理嵌入** | 纹理必须嵌入 GLB 文件内（不依赖外部文件） |
| **坐标系** | Y-up，角色面朝 +Z 方向 |
| **单位** | 米（1 unit = 1m），角色身高约 1.6–1.8m |
| **根节点** | 角色根骨骼位于原点 (0, 0, 0)，双脚站在 Y=0 平面上 |

---

## 3. 网格与拓扑

### 3.1 面数

| 物种 | 目标面数（三角形） | 最大值 |
|------|-------------------|--------|
| 人类 / 精灵 | 15,000 – 30,000 | 50,000 |
| 灵兽 | 20,000 – 40,000 | 60,000 |
| 机甲 | 10,000 – 25,000 | 40,000 |
| 幻形 | 15,000 – 30,000 | 50,000 |

> **性能红线**：总面数超过 50K 会导致低端设备帧率下降。面部区域（眼睛、嘴部）需要足够密度以支持 morph 变形时不产生伪影。

### 3.2 拓扑要求

- **全四边形拓扑**（导出时三角化）——关节处必须有 3+ 圆形边_loop_（edge loops），确保弯曲时不撕裂
- **面部拓扑**：遵循经典面部布线——眼周、嘴周各有同心圆边_loop_，鼻翼有独立边流
- **UV 映射**：非重叠，归一化到 [0, 1] 范围。头部和身体可以分 UV set 或合并在一张贴图上
- **mesh 合并**：尽量合并为少量 mesh（理想 1–3 个 draw call）。面部 mesh 可以独立（方便 morph 管理），但身体/服装应合并

### 3.3 眼睛与牙齿

- 眼球：独立球体 mesh，带瞳孔/虹膜纹理（或通过材质区分）
- 牙齿：独立 mesh（上下齿分开），位于嘴部内侧
- 舌头：独立 mesh（可选，但推荐——用于 viseme 口型同步）

## 4. 骨骼绑定

### 4.1 骨骼层级（人形物种）

角色必须包含完整的人形骨骼层级，命名遵循 **Mixamo / HumanIK** 惯例（保证动画通用性）：

```
Hips
├── Spine → Spine1 → Spine2 (Chest) → Neck → Head
│   ├── LeftEye / RightEye
│   ├── Jaw
│   └── (面部控制骨骼，如有)
├── LeftShoulder → LeftArm → LeftForeArm → LeftHand
│   └── (手指骨骼，拇指到小指各 3 节)
└── RightShoulder → RightArm → RightForeArm → RightHand
    └── (手指骨骼)

LeftUpLeg → LeftLeg → LeftFoot → LeftToeBase
RightUpLeg → RightLeg → RightFoot → RightToeBase
```

### 4.2 权重绘制要求

- 关节处权重过渡平滑（至少 2–3 个骨骼影响渐变区）
- 每个顶点最多 4 个骨骼影响（GPU 限制）
- 弯曲测试：肘部、膝部、颈部、手指弯曲时网格不撕裂、不穿插
- 面部权重：下巴骨骼驱动嘴部开合，眼窝骨骼驱动眨眼（如果不用 morph）

### 4.3 非人形物种

- **灵兽**：如果是四足，使用四足骨骼层级（quadruped rig）。如果是双足动物特征，使用改良人形骨骼（加尾巴骨骼）
- **机甲**：可以使用机械关节骨骼（无需严格人形），但需要等效的动画能力（头部转动、手臂抬起、行走）
- **幻形**：使用中性人形骨骼

## 5. Morph Targets（面部表情 + 体型变形）

> **这是整个规范最关键的部分。** Morph targets 驱动角色的面部表情、眨眼和说话口型同步。没有 morph targets 的模型在产品中不会有面部表情。

### 5.1 面部表情 Morph（必须）

以下 morph targets **全部必须提供**。命名遵循 **ARKit BlendShape** 惯例（引擎的别名系统也接受其他命名，但 ARKit 命名是首选）：

#### 眼部

| Morph 名称 | 说明 | 中性值 |
|-----------|------|--------|
| `eyeBlinkLeft` | 左眼闭眼 | 0 |
| `eyeBlinkRight` | 右眼闭眼 | 0 |
| `eyeWideLeft` | 左眼睁大 | 0 |
| `eyeWideRight` | 右眼睁大 | 0 |
| `eyeSquintLeft` | 左眼眯眼 | 0 |
| `eyeSquintRight` | 右眼眯眼 | 0 |
| `eyeLookDownLeft` | 左眼下垂（困倦/悲伤） | 0 |
| `eyeLookDownRight` | 右眼下垂 | 0 |

#### 眉部

| Morph 名称 | 说明 | 中性值 |
|-----------|------|--------|
| `browInnerUp` | 双眉内侧上扬（惊讶/开心） | 0 |
| `browInnerDown` | 双眉内侧下沉（悲伤/愤怒） | 0 |
| `browOuterUpLeft` | 左眉外侧上扬 | 0 |
| `browOuterUpRight` | 右眉外侧上扬 | 0 |

#### 嘴部

| Morph 名称 | 说明 | 中性值 |
|-----------|------|--------|
| `jawOpen` | 下巴张开（说话/visemes 的基础） | 0 |
| `mouthSmileLeft` | 左侧微笑 | 0 |
| `mouthSmileRight` | 右侧微笑 | 0 |
| `mouthFrownLeft` | 左侧嘴角下沉 | 0 |
| `mouthFrownRight` | 右侧嘴角下沉 | 0 |
| `mouthPressLeft` | 左侧嘴唇抿紧 | 0 |
| `mouthPressRight` | 右侧嘴唇抿紧 | 0 |
| `mouthShrugLower` | 下唇上缩（不确定/困惑） | 0 |
| `mouthLowerDownLeft` | 左下唇下沉 | 0 |
| `mouthLowerDownRight` | 右下唇下沉 | 0 |
| `mouthUpperUpLeft` | 左上唇上翘 | 0 |
| `mouthUpperUpRight` | 右上唇上翘 | 0 |

#### 颊部与鼻部

| Morph 名称 | 说明 | 中性值 |
|-----------|------|--------|
| `cheekSquintLeft` | 左颊上提（笑的组成部分） | 0 |
| `cheekSquintRight` | 右颊上提 | 0 |
| `noseSneerLeft` | 左侧皱鼻（厌恶） | 0 |
| `noseSneerRight` | 右侧皱鼻 | 0 |

#### 舌头（可选但推荐）

| Morph 名称 | 说明 | 中性值 |
|-----------|------|--------|
| `tongueOut` | 舌头伸出 | 0 |

> **命名兼容性**：引擎的 MorphController 维护了一个别名映射表。如果你使用的命名与上述不同（如 Daz 的 `Smile`、VRM 的 `happy`、Blender 的 `Mouth_Smile`），引擎也能识别——但**ARKit 命名是最安全的首选**。

### 5.2 Viseme Morph（推荐，用于精确口型同步）

如果需要精确的 phoneme 驱动口型同步（而非振幅驱动），请额外提供以下 viseme morph targets。命名遵循 **Preston Blair phoneme set**：

| Morph 名称 | 对应音素 | 说明 |
|-----------|---------|------|
| `viseme_PP` | /p/ /b/ /m/ | 双唇闭合 |
| `viseme_FF` | /f/ /v/ | 下唇贴上齿 |
| `viseme_TH` | /θ/ /ð/ | 舌尖贴上齿 |
| `viseme_DD` | /d/ /t/ /n/ /l/ | 舌尖贴上颚 |
| `viseme_kk` | /k/ /g/ /ŋ/ | 舌根贴上颚 |
| `viseme_CH` | /tʃ/ /dʒ/ /ʃ/ | 嘴唇收圆 |
| `viseme_SS` | /s/ /z/ | 齿间窄缝 |
| `viseme_nn` | /n/ /ŋ/ | 嘴微张舌抵上颚 |
| `viseme_RR` | /r/ | 嘴收圆微突 |
| `viseme_aa` | /ɑ/ | 嘴大开 |
| `viseme_E` | /ɛ/ /eɪ/ | 嘴中开微笑 |
| `viseme_I` | /ɪ/ /i/ | 嘴微开宽展 |
| `viseme_O` | /ɔ/ /oʊ/ | 嘴收圆中开 |
| `viseme_U` | /ʊ/ /u/ | 嘴收圆小开 |

> 如果不提供 viseme morphs，引擎会使用 `jawOpen` 的振幅驱动作为兜底——角色嘴巴会随音频音量开合，但不会精确匹配发音。

### 5.3 体型变形 Morph（推荐，用于角色定制）

以下 morph targets 允许引擎根据用户的角色描述（"高大的北欧战士" vs "娇小的东南亚少女"）调整体型。**每个物种都应提供**：

| Morph 名称 | 说明 | 0 = | 1 = |
|-----------|------|-----|-----|
| `Body_Height` | 身高 | 矮（1.5m） | 高（1.9m） |
| `Body_Weight` | 体重/胖瘦 | 瘦 | 胖 |
| `Body_Muscle` | 肌肉量 | 纤细 | 健硕 |
| `Body_Bust` | 胸围（女性适用） | 平坦 | 丰满 |
| `Body_Shoulders` | 肩宽 | 窄肩 | 宽肩 |
| `Face_Width` | 脸型 | 窄长脸 | 圆宽脸 |
| `Face_Jaw` | 下颌形状 | 尖下巴 | 方下巴 |
| `Face_Cheekbone` | 颧骨高度 | 低颧骨 | 高颧骨 |
| `Face_Nose_Length` | 鼻梁长度 | 短鼻 | 长鼻 |
| `Face_Nose_Width` | 鼻翼宽度 | 窄鼻 | 宽鼻 |
| `Face_Eye_Size` | 眼睛大小 | 小眼 | 大眼 |
| `Face_Lip_Thickness` | 嘴唇厚度 | 薄唇 | 厚唇 |

> 所有体型 morph 的**中性值（默认）必须是 0.5**（中间值），不是 0。这样引擎可以从中间态向两端调整。

## 6. 材质与纹理

### 6.1 PBR 材质要求

每个模型必须使用基于物理的渲染（PBR）材质：

| 贴图类型 | 分辨率 | 格式 | 说明 |
|---------|--------|------|------|
| **Base Color (Albedo)** | 2048×2048 或 4096×4096 | PNG | 无光照信息的纯色贴图 |
| **Normal Map** | 同上 | PNG | 切线空间法线贴图 |
| **Roughness Map** | 同上 | PNG（灰度） | 灰度值表示表面粗糙度 |
| **Metallic Map** | 同上 | PNG（灰度） | 灰度值表示金属度（机甲物种必备） |
| **AO (环境光遮蔽)** | 同上 | PNG（灰度） | 可选但推荐 |

### 6.2 材质分区

- **皮肤**：独立的材质 slot，使用皮肤 PBR 参数（roughness 0.5–0.7, metallic 0.0）
- **头发**：独立材质，使用 alpha 混合或 alpha 测试（发丝边缘透明）
- **眼睛**：独立材质，瞳孔/虹膜/巩膜分区。高光反射（roughness 0.1–0.2）
- **服装**：独立材质，便于换装系统替换纹理（roughness/metallic 按材质类型设置）
- **机甲特殊**：金属材质（metallic 0.8–1.0, roughness 0.2–0.4），发光部件使用 emissive 贴图

### 6.3 纹理注意事项

- 所有纹理必须**嵌入 GLB 文件**（Blender 导出时勾选 "Embed Textures"）
- 不依赖外部纹理文件引用
- 推荐使用 KTX2/Basis 压缩纹理（如 Blender 导出支持），可大幅减小文件体积
- 肤色 Base Color 不应包含烘焙阴影/环境光——这些由引擎的实时光照处理

## 7. 动画

### 7.1 必须提供的动画 clip

每个 GLB 文件应包含以下动画 clip（骨骼动画 + morph target 动画混合）：

| Clip 名称 | 持续时间 | 说明 |
|----------|---------|------|
| `idle` | 3–5s | 站立呼吸循环，含微小的重心转移和随机微动作。**必须无缝循环** |
| `speaking` | 3–5s | 对话手势循环——自然的手臂动作 + 头部微动。可叠加 morph 口型动画 |

### 7.2 推荐提供的动画 clip

| Clip 名称 | 持续时间 | 说明 |
|----------|---------|------|
| `thinking` | 3–5s | 思考姿态——手摸下巴或抱臂，头微仰 |
| `working` | 5–8s | 工作姿态——打字/操作手势 |
| `sleeping` | 5–8s | 睡眠——闭眼、缓慢呼吸、身体微沉 |
| `wave` | 2–3s | 招手问候（一次性，非循环） |
| `walk` | 2–3s | 行走循环（用于空间移动） |

### 7.3 动画技术要求

- **帧率**：30fps（最终在 60fps 渲染中插值播放）
- **循环动画**：首帧和末帧必须完全一致（无缝循环）
- **根运动**：idle/speaking 等原地动画不应有根运动（root motion = 0）
- **morph 动画**：idle 中应包含微小的眨眼 morph 动画（每 3–5 秒一次自然眨眼）
- **clip 命名**：clip 名称必须与上表一致（引擎通过名称查找）

> **Clip 命名至关重要**：引擎的 `AnimationMap` 通过名称匹配 clip（`idle`、`speaking`、`thinking` 等）。命名不匹配时角色会保持静止。

## 8. 各物种设计指引

### 8.1 人类（human.glb）— 写实

- **风格**：写实，接近 Reallusion CC / Daz Genesis 质感
- **体型**：中性匀称体型作为默认（morph 调整范围覆盖瘦弱到健硕）
- **肤色**：中性自然肤色（用户可通过 AI 贴图定制）
- **着装**：简约基础装（T 恤 + 长裤），作为服装热替的基底。服装 mesh 应有独立材质 slot
- **毛发**：短发（减少 alpha 透明度排序问题）。长发可作为可选配件
- **面部**：完整 ARKit 52 blendshape 表情集 + 体型变形 morphs
- **参考质量**：Reallusion Character Creator 4 / MetaHuman 级别

### 8.2 精灵（elf.glb）— 修长空灵

- **风格**：写实偏唯美，修长比例（身高比人类高 10–15%）
- **特征**：尖耳（提供 `Ear_Pointed` morph 控制耳尖长度）、高雅五官
- **肤色**：可偏冷色调（象牙白/淡蓝/淡紫），或自然肤色
- **着装**：飘逸长袍/斗篷基础装
- **毛发**：长发（可飘动）
- **面部**：完整表情 morph 集。精灵特有的微表情（高傲、空灵）可作为预设

### 8.3 灵兽（spirit_beast.glb）— 动物特征

- **风格**：写实动物 + 拟人化（双足站立 OR 四足）
- **建议**：双足拟人化（便于复用人形骨骼和动画）。如果是四足，需要独立的四足 rig 和动画集
- **特征**：兽耳、尾巴（带 tail 骨骼）、毛皮纹理、瞳孔形状（竖瞳/大瞳）
- **毛发**：毛皮纹理（fur texture），或使用 hair card 技术
- **面部 morph**：兽化表情——呲牙（`jawOpen` 加尖牙露出）、耳朵转动（`ear_Twitch`）、瞳孔收缩
- **体型**：比人类略矮但更敏捷

### 8.4 机甲（mecha.glb）— 机械

- **风格**：写实机甲，可见的关节和装甲板
- **材质**：金属 PBR（metallic 0.8–1.0），发光部件使用 emissive 贴图（眼睛、核心、推进器）
- **面部**：可以是屏幕/面板（用 emissive 贴图变化模拟"表情"），或简化的机械眼
- **morph 替代**：如果机械脸不适合传统 morph，可以用骨骼驱动的"表情"（下颌开合代替 `jawOpen`，面板倾斜代替头部表情）
- **动画风格**：更精确、机械感的运动（少缓冲、多定格）
- **体型**：比人类略大（1.9–2.2m），宽阔肩部

### 8.5 幻形（shapeshifter.glb）— 中性高度可塑

- **风格**：中性、无明确性别特征，略带半透明/发光质感
- **核心需求**：**最大化 morph 可塑性**——这个物种的设计意图是"可以通过 morph 变成任何形状"
- **体型 morph**：提供比其他物种更多的体型 morph 滑块（额外的肩宽、臀宽、四肢长度等）
- **材质**：略带 subsurface scattering 效果的皮肤（`MeshPhysicalMaterial` with transmission），或微弱自发光
- **面部**：中性五官，完整表情 morph 集
- **特殊 morph**：`Glow_Intensity`（控制自发光强度）、`Transparency`（控制半透明度）

## 9. 性能约束

| 指标 | 目标 | 红线 |
|------|------|------|
| **文件大小** | < 5 MB | < 15 MB |
| **三角形数** | < 30K | < 50K |
| **Draw calls（mesh 数）** | 1–3 | < 10 |
| **纹理总内存** | < 20 MB | < 50 MB |
| **Morph target 数量** | 30–60 | < 64（GPU 硬限制） |
| **骨骼数量** | < 80 | < 120 |

> **运行环境**：Electron (Chromium WebGL)，目标 60fps，中端 GPU（如 GTX 1060 / M1 集显）。透明置顶窗口模式下可用 GPU 资源有限。

## 11. 验证方法

交付后，我们将使用以下流程验证模型：

1. **Three.js 加载测试**：在浏览器中加载 GLB，确认模型、纹理、骨骼正确显示
2. **Morph 检查**：遍历所有 morph target，逐一激活到 1.0，确认变形正确无伪影
3. **表情测试**：运行引擎的 16 种情绪预设（happy/sad/surprised…），确认面部表情正确组合
4. **动画测试**：播放 `idle`、`speaking` 等 clip，确认循环无缝、动作自然
5. **性能测试**：在透明窗口模式下运行 5 分钟，确认 60fps 稳定、CPU/GPU 占用合理
6. **换装测试**：通过引擎的 setOutfit 接口替换材质颜色和纹理，确认热替正常
